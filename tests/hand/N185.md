# n185: a row of stats typed as one note comes out big, each value over its small label

Found in n175, n177 and n184 (round 43 c5 climbing gym).

## What was built
- **A stats row.** Three short lines were drawn under the button and one note typed under them:
  "£14 day pass, £52 monthly, 6–23 open daily; big bold, label under". Every build put the values on the drawn
  lines at body size (15px; the target is about 30px). `statrow.ts`: a note whose comma parts are each a value
  (number, price, range, percent, a value with a short unit) and a short label, two or more of them, with a size
  word (big, huge) or "bold ... label under/above", is a stats row. The build is told each value is its own element,
  big (about 30px, huge about 48px) and bold, the label a small muted element under it (above when typed so), in
  the typed order on the lines drawn for them. Checked on the page (value size, bold, label side and size).
- **It is never a body-size table row.** The first live run built the values at 30px and passed the new check, but
  the n71 table-row rule ("short values on a line stay body size") failed it and the repair shrank them back to
  15px. `linespread.ts` `isTableRow`: a stats row is no table row.
- Scanned all 1,244 notes typed in earlier hand steps: three stats rows found (this gym, round 41 ski lodge,
  round 39 observatory), no false hits (prices lists, ticket rows, tables, crypto rows stay as they were).
- Tests: `packages/pipeline/tests/n185-stat-rows.test.ts` (8).
