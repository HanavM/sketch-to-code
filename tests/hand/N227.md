# n227: a count down on one drawn box repeats the box, one typed row in each

Found in n222 (round 47 e5, budget donut). One wide flat box and the note "x4 down, colour square left: Rent, $960; Food,
$600; Fun, $480; Transport, $360" gave all four rows squeezed into the one box. A fix asking for 4 cards did nothing. Three
more drawn boxes got invented rows (Subscriptions $85, Utilities $140, Savings $300), and the page scored 90.3 anyway.

## Causes found
- **Two reasons the count was ignored.** The direction word was not read when a comma followed it ("down,"), and any box
  half the page wide or more was taken for a list panel and never repeated.
- **Nothing tied the typed rows to the copies.** The rows rule said "one per drawn row", and one row was drawn.

## What was built (zero tokens)
- **One flat box, a way down and that many rows typed is one row:** it repeats down at the drawn size, however wide, each
  copy holding one typed row, name at the left and value at the right. A box taller than 120px, or with marks drawn inside,
  is still the panel the rows go in.
- **Boxes already drawn below are the next rows,** at their drawn spacing (unit test only, not seen live).
- **A colour mark in each row takes the colours tapped in a ring,** in the order tapped, when there is one colour per row.
- **The tap fills every copy, the pen is its thin edge.** Words before the colon are how the rows look, never printed.
- **Checked per row:** each cell is on the page, inside its own box.
- Tests: `packages/pipeline/tests/n227-rows-repeat.test.ts` (10). Demo: `out-n227/n227-demo.gif` (target, sketch, before, now).

## How far it reaches
Scanned all 1,653 distinct kept notes against their drawn strokes: **only this one note fires it.** So this is narrow. Sketchers
have mostly not typed this shape, possibly because it did not work; a fresh round will show whether it gets used.

## Did it help
- **Rows right in 2 builds of 2 with no fix:** four separate boxes at the drawn place, names, values, colours in order, nothing
  invented. Before, no number of fixes got this.
- **Up 3 to 8 points on the first build (76.0 to 79.0 and 83.9),** at 53 words against 92 and no fix against three.
- Still under n222's 90.3, which had a right donut after its fix. The gap is the donut, not the rows. Two builds is a small sample,
  and this page has been seen before, so none of this counts toward done.

## Not done, or still off
- **The donut is still a fade in both builds, and try 2 lost its hole.** That is n226, next.
- **"A run that changes nothing says so" was not built here:** n190's fix check already fails such a run. I did not test whether a
  person is shown that. It stays a loose end.
- The colour marks came out smaller than the target's squares. The sketch did not say how big.
- The heading crowds the line under it in both builds; not looked into.
