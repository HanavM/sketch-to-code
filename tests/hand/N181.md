# n181: every filter option gets a box a person can see

Found in n180 (round 43 e4 pet adoption, replay): the filters note lists nine options in three groups and names the
three that are checked ("...; Dogs, Adult, Medium checked orange"). Builds drew the checked boxes, but the six unticked
ones came out with a near-white border nobody could see, and no check looked.

## What the run records showed
- The checkbox-list reader (n112) only knew ticks typed as ✓ after each option and "Name: a, b, c" groups. The pet note
  uses "Animal (Dogs, Cats, Rabbits)" groups and a "Dogs, Adult, Medium checked" tail, so it was never read as a list:
  the build guessed, and nothing checked it.
- The checklist check looked only at the words, never at the boxes.

## What was built
- `checklist.ts` `checklistOf`: a last part "A, B, C checked / ticked / selected [colour]" marks those options as ticked;
  "Heading (a, b, c)" groups are read with their heading. Plain lists ("Dogs, Cats, Donate", a name list, a card
  description with a bracketed colour list) stay plain.
- Brief: every unticked option still gets its own empty box, outlined in a visible mid grey, never a faint line; the
  word "checked" is never printed.
- Check `optionBoxFaults`: each option label (its letters, not its whole `<label>`) must have a small square just left of
  it on its row, and an unticked one must show a border or fill a person can see. When the same word is also a nav link
  ("Dogs, Cats" up top), the copy with a box beside it is the option.
- Tests: `packages/pipeline/tests/n181-checklist-boxes.test.ts` (8, on the real pet note and its built shapes).

## Did it help
- The filter list: all nine boxes visible, the three named ones ticked, in all four runs (was six invisible boxes in
  every earlier run). The check now sees this and passed in both runs after its two fixes.
- Likeness did not move up: 76.7 and 65.3 against 81.8 and 75.4 in n180. What decides the pet score now is the card
  tints (one run pastel, the next saturated mint and yellow) and the card heights, not the filters.
- Card tint drift (the second half of this node's title) was not built; it is the next step.
