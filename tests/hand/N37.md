# n37: a fix note after a build is checked on the page like a build

Round 32 (n35) showed three of four fix notes typed on a built page made it worse, with nothing checking:
the heading broke down onto the date, the subtitle moved up into the heading, "no panel" painted the panel
pink. A fix run has no drawn marks, so none of the build checks applied.

## What was built (packages/pipeline/src/fixcheck.ts, wired into run2)
- **Words that were apart stay apart.** On a page that was already built, any two pieces of text that did not
  touch before the run and overlap after it fail the check, named by their words; so does text that runs
  under a painted shape (a disc, a card) it was clear of. Repair rounds are told exactly which.
- **"no panel / background / card / box"** means the element the note sits on stops painting (transparent, no
  gradient, border or shadow), checked on the page; recolouring it fails.
- **A note naming parts on a wrapper** ("bars", "cards", "links") tells codegen to change the parts, not the
  wrapper's own look.
- **Put back.** A fix that still breaks either rule after its repairs is undone: the page goes back to exactly
  how it was before the note, and the run says so ("the fix ran X into Y: put the page back").
- Bench: `replay.mjs --fixes` replays the first-pass sketch, then types the same fix notes at the same spots.
