## What went wrong (gaps found)
- **A note with a number in a box becomes a stat card** (e1, e4): "Standup 9:00 – 9:45" was built as a
  huge "9:00" over "Standup 9:45"; chat bubbles "Mia · 2:14 pm above; Copy is final..." became a big
  "2:14 pm" with the message text **dropped**, and "Great. Shipping at 5 then." became a big "5". The
  stat-card reading should only fire when the number stands alone (or the note says so). Biggest lead.
- **A box drawn in a light pen with no tap is filled with that grey** (e1 grid, e2 cards, table, search,
  e4 inputs): the person meant an outline. Each took a "white" fix. Same family as n78 (pen box = outline).
- **A stroke that starts on or near a note chip is lost** (e4 bubble, e5 products card): the chip of an
  earlier note sat where the next box began; the stroke vanished with no sign. Had to move the note and
  redraw. Lead: chips step aside while drawing, or the stroke goes through.
- **Dragging a note onto a freshly drawn box says "whole sketch"** (e4): only deleting and re-adding the
  note bound it.
- **A fix note only reaches the element it lands on** (e4): "chat bubbles: message text only..." fixed
  one bubble and then **made up its text** ("Shipping at 5 today — works for everyone?"); the other two
  stayed stat cards. Fix notes need the same group reach as sketch notes, and never invent copy.
- **Typed copy changed**: "freshbox" built as "FreshBox", "3 items" as "Order summary" (e3), "Search
  input" and "above" printed literally (e4).
- **A group note's values are not split per mark** (e5): four stat cards got "$84,210" three times; the
  note bound to 2 of 4 boxes. Same as the c3 lineup (2 of 3).
- **Drawn order not kept** (e5): pills 7 days / 30 days / 12 months built in another order; a fix
  swapped them but moved the highlight too. Toggle colours inverted on e1 and a fix note did nothing.
- **Slash in a list row** (e4): "#design / New logo is up, Ravi Patel / sounds good" split at commas,
  not slashes, so names and previews were shuffled across rows.
- **Headers and rows**: a note dropped on a table's header line bound to the whole table (e2), header
  row and dividers missing on the first build; weekday headers centred, not left (e1).
