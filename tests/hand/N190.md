# n190: a fix changes only what it names, and says so when it changes nothing

Found in n188 (round 44 e3 photo editor, e5 delivery tracker).

## What was built
- **A typed colour is never "snapped" onto a font size.** The finishing pass swaps a near-copy colour literal for
  the app's own colour class. It counted `text-[15px]` as a colour class (any `text-[...]` was), so a 15px grey
  label put "text-[15px] = grey" in the palette, and a typed orange `text-[#ea580c]` was then rewritten to
  `text-[15px]`: the class lost its colour. That is why e5's orange arrival line turned black after the fix in n188.
  It hit 5 of the kept run records since round 42 (podcast, airline, gym, notification settings, delivery tracker).
  Now only `[#hex]`, `[rgb(...)]`, `[hsl(...)]`, `[color:...]` count as colours, and a snap to the same literal is
  not logged.
- **Colours not named stay.** A fix on a built page is told the page's strong colours ("line #ea580c (orange) on
  path ...; text #ea580c on "Arrives today ...""), and after the edit every element is compared with itself before
  the fix: a fill, text colour or svg line colour that changed outside the marks the notes sit on, to a colour no
  note names (or away from a strong colour of its own), is a failure the repair must undo. The page snapshot now
  records an svg shape's own stroke and fill, so a repainted drawn route is seen too.
- **A fix that changes nothing says so.** When a fix note was typed and nothing visible moved (same elements,
  places, words, looks), the run fails with "this fix changed nothing visible on the page" instead of reporting its
  checks satisfied (e3 in n188 edited one icon file and said "satisfied").
- **A whole-sketch fix note counts as said.** Notes typed on the whole sketch reach the run as run notes, not action
  notes, and the n102 copy checks read only action notes: "delete texts 4 grey squares" was put back as "emptied
  copy" on the first e3 try below. The copy checks (and the new colour check) now read run notes too.
- Tests: `packages/pipeline/tests/n190-fix-names.test.ts` (10); n102's "unchanged page" test now expects the new
  "changed nothing" verdict.

## Did it help
- e5: the orange arrival line no longer loses its colour (a real bug, now gone); 47.0 → 63.6 / 66.5. The route
  still turns grey: the tool read "grey track" as the route itself (its reading said so before the build) and
  aimed the edit at the route, so the change was on the marked thing and not flagged. That is a reading question
  (which "track"), not a fix that spread.
- e3: the thumbnails kept their pen colours through the fix (n188 greyed them), and the asked deletion is no longer
  undone. But the fix took "delete texts ... 5 sliders" as deleting the slider names and painted "sky" into the
  crop frame: 68.1 → 70.1 (try a, whose fix was put back, kept the better first build: 77.6).
- Fix notes that name a part ambiguously ("track", "sky") still land on the wrong part; next: show which element a
  whole-sketch fix will change before it runs.
