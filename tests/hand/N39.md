# n39: a fix note that names a part as a place is about the part next to it

Round 32 c2 (n37 try 1): "one line, below heading" was typed on the heading's lower edge, meaning the
subtitle under it. The note took the element under the pointer, the heading; the fix put the heading on
one line and ran it under the disc (67.2). On try 2 it reached the subtitle only because the heading came
out smaller. Which part a fix changed was luck.

## What was built (packages/overlay-client/src/fix-subject.ts, wired into commitNote)
- When a note's words place something against a named part ("below the heading", "under the title",
  "next to the button") and the pointer landed ON that named part, the note goes to the nearest other part
  on the side the words point to (below for "below/under", above for "above", and so on), within ~90px.
  Nothing near on that side: the pointer's pick is kept.
- The status line says so: "on this element · p (the part below the heading)", and the dashed outline sits
  on the new part, so a wrong pick is still seen and can be dragged.
- Unit tests: the n37 c2 geometry as a fixture, wrong-side and out-of-reach cases.
