## What went wrong (gaps found)
- **A small filled box inside a light outline card ate the card, and its tap painted the whole page**
  (e4: the yellow folder icon in the first card: card 1 vanished from the marks and the build, the page
  became a yellow gradient). A fix note made the page white; another put the first card back.
  Lead: a tap inside a small box inside a card fills that small box, never the page; nested boxes stay nested.
- **A list note across a row of drawn cards is pasted as one card's text** (e4: "Brief.docx 2 MB, Cover.png
  4 MB ..." printed verbatim in card 2, the other cards empty; same on row 1). Each row needed its own
  fix ("one name and size per card"). Lead: a comma list on one of N same boxes in a row is spread one per box.
- **Notes typed just under picture boxes land inside the pictures** (e5: name, area, price drawn on the
  colour blocks). A fix moved the text below but shrank the blocks to 80 px (drawn height lost).
  Lead: a note under a box (not on it) is the caption below it; the box keeps its drawn height.
- **A lone ring at the top of a list region is not row 1's avatar** (e1, same as open n114: the ring
  floats, rows start below it; a fix "circle on each" added rings at the right end instead).
- **A white line under a big number became a rule** (e1 balance card), removed by one fix note.
- **A note typed in empty space binds to a far full-width divider** (e2: the day labels note and the
  buttons note both bound to the header line). The build was still right, but day labels came out very faint.
- **A one-word tag became a dot** (e3: "urgent orange right" built as an orange dot, word lost).
- **Words run long on app pages** (median 61): list content (rows, card names) is the bulk. Same family as
  the list-spread lead above: if one note fills a row of drawn cards, fewer words are needed.
