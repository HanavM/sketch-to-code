# n8: counts and fixes keep the drawing (goal 2026-10-27)

What was built (branch try/n2-shape-vocab):

- **Typed counts are exact** (`packages/pipeline/src/counts.ts`). "5 teams",
  "24 numbered rows", "three cards" are read from the notes. Codegen is told
  each is exact, and a content count inside a slot count ("5 teams" in "24
  rows") means all the slots are built and only that many are filled; the rest
  stay empty. After the build, repeated groups (rows, cards, tabs) are counted
  on the page; a group padded past the count fails the check and goes to the
  repair round.
- **Boxes drawn earlier stay where drawn** (`shapemark.ts`, kept marks). Every
  drawn box or ring that landed is remembered in the project. Each later run
  pins it to the element built for it (as found when the run starts), tells
  codegen to keep that element exactly there, and checks it afterwards like a
  drawn rule. A note that asks to move or resize the very block it sits on is
  obeyed, not undone; a block that is gone or moved on purpose is not pinned.

baseline filled all 24 with invented teams). In try 1 the kept-box check
mistook a page wrapper of about the grid's size for the grid, so the fix note
still pulled the grid 41px up. Now each kept box is pinned to its own element:
in try 2 the fix ("title small, menu on same line") moved the menu up beside
the title and the grid did not move at all. That fix took 40 s instead of
about 2 min. The score stays in the 30s because of layout: the grid's columns
and the formula bar don't line up with the target. Two runs of the same sketch
