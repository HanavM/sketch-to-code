# n115: a run never waits forever when the dev server dies

Found in round 38 (n113 tries 2 and 3, hotel): the app's dev server died silently mid-run, right after an edit.
The bar sat on "making your change" until the 10-minute watchdog, then said only "run may have died"; the run
left no record, and the hand session waited on with nothing to show.

## Built
- **Overlay** (`overlay-client`): when the event stream drops during a run, it asks the server if it is there
  (once a second). After 8 s with no answer it ends the run and says plainly: "the dev server stopped while
  making your change — the page on disk is kept as it was left; start the dev server again to carry on".
  If the server answers again first, nothing changes.
- **Plugin** (`vite-plugin/interrupted-runs.ts`): when the dev server starts, every run that started (stage log)
  but never ended (no record) gets one: interrupted, the last stage it reached, how far in, and that the page on
  disk was kept as left. The count is logged and returned by `/@s2c/ping`.
- **Hand session**: watches the server process; if it exits mid-run, stops waiting at once, writes
  `run<n>-server-died.json` (exit code, the bar's words, the server log tail), restarts the server and scores
  the page as the run left it.

The bar said the dev server stopped about 9 s later, the session stopped waiting (run over at 227 s instead of
waiting up to 23 min), the restarted server wrote the run's record (`interrupted`, last stage "Write src/App.tsx"),
and the half-built page on disk was kept and scored. The cause of the original deaths is still unknown (the
server log ends with a plain "Killed", which points at the process being killed from outside, e.g. memory);
the server log is now always kept with the record.
