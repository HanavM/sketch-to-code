# N100: a number among words is copy, never a stat card

Gap (n98, round 37): a box whose note held a time or a number among words was built as a stat card. Calendar
events "Standup 9:00 – 9:45" became a huge "9:00" over "Standup 9:45"; chat bubbles "Mia · 2:14 pm above; Copy is
final. Can someone check..." became a big "2:14 pm" with the message dropped; "Great. Shipping at 5 then." a big
"5". Each page needed a fix note to undo it.

## What was built
- **Prose numbers are copy** (`statcard.ts proseNumber`, used by `statOf`): a box's notes are never a stat card when a
  note holds a time of day (9:00, 2:14 pm, 10 AM) or a range (9:00 – 9:45, 12–14), a sentence (sentence punctuation,
  or more than six copy words in one phrase), or a number with copy words on both sides ("Shipping at 5 then"). A
  note that says it is a stat ("stat", "big number 2:14") still is one. Zero tokens.
- Scan of every note typed in rounds 31-37: 24 notes stop reading as stats (events, messages, dates, departure
  rows, sentences); every real stat (Income 3,800; 6 on loan; 12480 kg; Revenue $22.8k +9%; $84,210...) still does.
- Tried and put back: a fix-note brief saying "this note is about every one of the set" (chat bubbles:, events:,
  each row:). Live, the chat fix "chat bubbles: message text only..." reached both grey bubbles but emptied their
  text, and "each row:" copied each name into its preview line. Worse than n98 (72.2 vs 83.1), so reverted; set reach
  needs a page check that a fix never empties or duplicates copy (new node n102).
