# n208: the top bar keeps its drawn height

Found in n207 try 2 (round 45 c4, bike repair): the header came out 93px tall where the drawing has the hero start at
79px, so every block below rode 14px low. The page-shift check named the shift but only said "find that one space
(a taller bar, page padding, a margin)", and neither repair round took it out (80.5).

## What was built (zero tokens)
- **The shift names the bar** (`barCause` in `drift.ts`): when the first block that is off sits right under a
  full-width bar at the very top (bar bottom within 8px of that block's built top), the check names that bar (tag,
  words, source line), its built height and the height the drawing gives it (built height minus the shift), and asks
  for exactly that height, words centred, nothing below touched. Used by both the small-shift and the drift messages.
- Never picks the whole-page wrapper (over 200px) or a box narrower than 60% of the page; says nothing when the bar
  ends well above the shifted block (the space is elsewhere then). A bar built too short is told to grow.
- Tests: `packages/pipeline/tests/n208-top-bar.test.ts` (4).
