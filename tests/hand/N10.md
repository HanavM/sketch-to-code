# n10: colour from ink (goal 2026-10-27)

What was built (branch try/n3-ink-style, on top of n9):

- **Tap to colour in.** Pick a pen colour and tap: inside a drawn box, ring or
  closed blob, that block is filled with the colour; on bare page, the page is
  that colour. Two or more page taps in different colours make a gradient that
  runs from the first tap towards the last. The fill shows on the sketch the
  moment the pen lifts (half strength, so the marks still read), and the bar
  says "filled this mark #hex" or "page colour #hex (gradient ...)".
- **A mark drawn in a colour is that colour.** A box or ring drawn with a
  coloured pen is filled with it; a line or text squiggle drawn in colour sets
  that text's colour.
- **Same rule on both sides.** What a tap fills is decided in `@s2c/ink`
  (`inkFills`, `pageFill`), so the overlay shows exactly what the build is
  told. Taps never reach the reading as strokes (they used to be thrown away;
  a stray dot would have been a mark on whatever it sat on).
- **Told exactly, checked on the page.** Codegen gets a COLOURS FROM THE INK
  block (exact hex per mark, the page gradient) that outranks colour words;
  after the build each colour is checked on the element built for its mark (or
  the page) and a miss goes to the repair round.

## Gaps found this step
- The check read a white headline line as missing (its two-line heading box is
  centred below the first line), which cost the sunset a repair round; fixed
  (text colours are looked for across the line's band), with a test.
- A tapped glow comes out the exact hex but faint: blur and low opacity spread
  it thin, so the pink and cyan read much dimmer than the target.
- A note dropped inside a small box that sits in a big box still binds to both
  ("on these 2 boxes"), so the badge and button notes also reach the card.
- Headline still built a little low and the subtitle crowds it (n11's gap).
