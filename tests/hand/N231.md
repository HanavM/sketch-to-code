# n231: a repair that stops twice with no edit gets one small last try

Found in n228 (timesheet try 2): 14 faults, the repair thought 155 s with no edit, the fresh repair 90 s with no edit, and
the run kept a first build that was off the drawing (58.2). The same double stop is on record for gradebook (n213).
In 75 recent runs (n200 onward), 5 had a repair stop with no edit; 2 of those also lost the fresh try.

## Causes found
- **After the fresh repair stopped, nothing else was tried.** The page stayed as built, however wrong.
- **The fresh repair still has a lot to weigh:** the reading, every action as JSON, "check the codemod edits", three
  problems, and a file to read first, all inside 90 s.
- **Found on the way:** one good fix often leaves the share of checks passing the same. Gradebook stayed at 83%, and "no
  improvement" ended the run right after the fix.

## What was built (zero tokens until it fires)
- **A last try** (`lastRepairBrief`): a new agent told one problem, the biggest, with the page's text in the message so it
  has nothing to read, and 150 s. A page over 60,000 characters is read from its file instead.
- **One more round after it:** a same-share result after the small fix does not end the run. A worse page is still put back.
- **Later rounds in that run stay short:** only the biggest few problems go.
- `S2C_FORCE_REPAIR_STALLS=n`, a bench knob: the first n repair turns stop at the first look, so this path can be tried on
  a real page. Off unless set.
- Tests: `packages/pipeline/tests/n231-last-repair.test.ts` (4). Demo: `out-n231/n231-demo.gif`.

## Did it help
- **The last try made an edit every time it ran: 3 of 3, in 8 to 10 s, for about 3k tokens.** A stopped repair had made none
  in 90 to 155 s.
- **Timesheet ended at 83.6 and gradebook at 70.3 and 73.3.** Be careful with these: the builds differ from run to run, so
  the gap to 58.2 is not all this change. What it shows is that the path finishes and does no harm.
- **One of the three edits made the page worse, and it was put back.** So the last try is safe, not always useful.
- **The stops here were forced at once, not real ones.** A real stop has not happened on this path yet, and the case that
  matters is a page with many faults. The next fresh round will show whether it fires and what it does.
