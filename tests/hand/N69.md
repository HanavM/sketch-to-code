# n69: look-alike rows keep their own words

Replayed the n66 sketches of round 34 e1 (recipe: 16 strokes, 10 notes) and e4 (helpdesk: 20 strokes, 15 notes)
word for word: first build only, no fix notes, no note drags.

## Gap (from n66)
- **Recipe:** five 22px checkboxes 38px apart, each ingredient typed to the right of its box. Notes bound to "these
  2 boxes", "these 5 boxes", the "Ingredients" line above, or nothing ("placed here"); six drags did not fix it. The
  build repeated one row's words ("Garlic clove" x3) and a fix note changed no file.
- **Helpdesk:** three chat bubbles, each message typed inside its bubble. The first message filled all three; the fix
  invented new messages.
- Two hidden causes, found while replaying: "2 lemons" and "3 cloves garlic" were read as group notes ("2 of the
  marks"), and "...every time I click it" was read as "every one of them", so the first message was told to go on
  EACH bubble.

## What was built
- **Which mark a note is about** (`notefocus.ts`, shared by the overlay and the build): among look-alike marks
  (like-sized closed shapes in a column or row) a note goes to the one it is inside, or level with; a note typed on
  a list mark's row (to its right, up to 240px) is that mark's even when a line above is nearer, and the overlay
  attaches it there rather than "placed here".
- **A count is copy, not a group:** "3 cards", "every box" still name a group; "3 cloves garlic", "2 lemons",
  "every time" do not (the noun must name a drawn thing).
- **Told and checked** (`rowwords.ts`): a box or ring with its own note keeps those words. Two or more look-alike
  marks with different words are a list: the build is told each item's exact words in drawn order, and the page is
  checked that each mark has its own words beside or inside it, naming what is there instead (another item's words,
  or made-up ones). A note that only describes a mark ("purple left edge") is not its words.
