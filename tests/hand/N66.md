## What went wrong (gaps found)
- **Repeated rows lose their own words** (e1, e4): the build made one component for the list and repeated
  one note's text ("Garlic clove" x3 for parsley, garlic, olive oil; the first chat message in all three
  bubbles). A fix note listing the three right texts changed no file (changedFiles empty) and was reported
  done. In e4 a fix "each bubble shows its own typed message" invented new messages instead of using the
  typed ones: the fix never sees the earlier notes. Lead: every note bound to one of several look-alike
  marks is that mark's own content, checked on the page; a fix can read the original notes.
- **A note dropped next to a small box binds to a group of boxes** (e1): notes typed beside five 22px
  checkboxes landed "on these 5 boxes", "on these 3 boxes", "placed here"; dragging them onto each box still
  said "on these 2 boxes" or "whole sketch". Six drags, still wrong.
- **A colour tap on a thin line becomes a page fade stop** (e5): teal and mint taps on the stepper's two
  connector lines turned the whole page into a teal diagonal gradient (shown on the sketch too). One fix
  note flattened it. Lead: a tap within a few px of a line colours that line.
- **Drawn span does not set spacing** (e3, e2): the day-letter line was drawn 500px wide over seven
  columns 80px apart; dots and letters were built 56px apart, crowded to the left (layout 49%). Table
  columns spread to the page width instead of where a person would put them (flight at 870 vs 565).
- **Words on a long row line are sized to fill it** (e2): n62's "a sentence on one drawn line runs its
  length" made each table row giant (60px) text. One fix note brought them back. Lead: a line with several
  short values (a table row) is not a sentence; don't stretch it.
- **A clock typed as "14:32" became a live clock** (e2) showing the real time.
- **Text starts indented from its drawn line** (e1): title and meta 15-30px right of the drawn start.
