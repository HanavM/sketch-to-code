## What went wrong (gaps found)
- **A count on a drawn line invented its contents** (e5): "x4 down: Loan amount $24,000 half; Term 60 months 70%;
  ..." on the first slider printed "down: Loan amount $24,000 half" as a label, then made up Vehicle price, Monthly
  budget and Trade-in rows with invented figures. The three other grey lines I drew were ignored, the sliders
  stacked 90px apart, not 120. The first result had no tracks at all. The fix built the sliders but kept the made-up
  rows. Lead: items listed after a count are the items, verbatim, one per drawn line; never invent a row, and
  never print the count words.
- **A tap meant as a small dot filled the whole box around it** (e2): green and grey taps for status dots, inside
  the table outline, painted the first row bright green and the rest of the table grey. It was a clean misread of
  my mark: the tap's colour differs from the box's. One fix note cleaned it up in 105 seconds. Lead: a tap in a colour
  other than the box's own pen is a dot where it landed, never a fill.
- **An untapped outline chip with a count built filled** (e4): one outlined time chip, "x12" note, and a separate
  filled one: all twelve built filled. Fix note (30 seconds, 5 words) put them right.
- **A drawn search box and button did not keep their widths** (e1): box drawn 40-940 and button 960-1100 built
  to the page edge (box to 1078, button 1099-1240). Same for the four covers: wider than drawn, gaps smaller.
- **A note inside a ring was dropped** (e3): "Heating to 22°" never appeared; the big "21°" did.
- **Invented active highlight on a nav item** (e2): Team got a purple pill; the target only has it bold white.
- **Short rows with a value put the value on a second line** (e3): "Living room 21°" as name over value, not side by side.
- **A word typed inside a pill note as a colour went solid** (e1): "On loan red pill" built solid red with white
  text; the target is a pale red pill. My note did not say pale; not a tool fault.
