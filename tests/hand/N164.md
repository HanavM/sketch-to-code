# n164: style words after a heading are never printed

Found in n161 (round 42 c3, ski lodge) and again in n213 (round 41 c4, chess night). The note "CHECK / MATE huge bold caps,
MATE outlined only" built a second heading line reading "MATE HUGE BOLD CAPS, MATE OUTLINED ONLY". "First tracks, / warm
fire, huge bold, right" lost only "right", so "huge bold" could become a third line. Nothing told the build these were
looks, so nothing checked them either.

## What was built (zero tokens)
All in how a note is split (`noteParts`, `typedcopy.ts`):
- **A look for one word of the copy is a direction.** ", MATE outlined only" names a word already in the copy, then look words.
- **More than one look tail comes off**, when the earlier one holds a size or weight word and no number.
- **A look run with no comma comes off copy that has commas**, when it is two words or more ("Coffee, cake & tiles huge bold").
- Kept as copy: a word ending a sentence ("after dark. huge bold"), one-word tails ("Think small, dream big"), stats with their
  number ("Paid, 612 big, +3% green").

Replayed over all 1,588 notes typed so far: 16 now split differently, each read by hand and each right.
The build is told the split, and the page already fails if it prints a direction or a look run.

## Did it help
- **Style words stayed off the page in all four builds, with no fix note.** Chess went from 59.5 to 79.3 and 83.3, with 21 fewer
  words, because the fix notes are no longer needed. Both pages have been seen, so neither counts toward done.
