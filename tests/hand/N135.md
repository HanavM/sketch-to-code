# n135: a selected chip drawn in a strong pen is pale with a border; a heading on a drawn line is never a link

Found in n127-n134 (round 39 e4 vet booking): the "Biscuit selected, avatar" pill, drawn in a mid-green pen with
no tap, came out a solid green block in every build; the screenshot shows a pale green pill with a green border
and a round avatar. And "Book a visit" (typed on a dark green pen line) was read as a link because it contains
"visit", so it was told, built and checked underlined; "Summary" came out underlined beside it.

## What was built
- **Selected chips** (`inkcolour.ts` `selectedChip` / `selectedBuilt`, used in `intent2.ts`): a chip-sized box in a
  strong coloured pen (not light, not near-black), no tap, whose own note says selected / active / current / chosen /
  picked / checked, is a pale tint of the pen colour with a 2px border in it; avatar / dot / icon / photo on it adds
  a small round mark at its left. Told to the build and checked on the page (solid block, no border, or missing dot
  fail and go to the repair round). A tap or a fill note still gives the solid block. Such a chip is also always kept
  a box, even when its group is read as a picture (n134).
- **Links need link phrasing** (`linkline.ts`): an arrow, a link verb first (See, View, Learn, Visit...), or ending
  in more / see all / our work; and a dark pen (by lightness, so forest green counts) is never a link colour.
- **Underlines caught** (`textrules.ts`): words on a drawn line built with a text-decoration underline now fail the
  "lines drawn for words" check (only bottom borders were caught before).
- Zero tokens, no model call. 6 unit tests (1 n134 test changed: "Biscuit selected" is now a chip on purpose).
