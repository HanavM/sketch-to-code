# n43: do the 3-line heading and own-words checks carry over? And a fix with nothing to change says so

## What was built
- **A fix note that asks only for what its part already is runs nothing** (packages/overlay-client/src/fix-subject.ts
  `alreadySo`, wired in main.ts): each clause of the note is either a place ("below heading", "here") or a look
  (one line / 2 lines / bold / not bold / centred / capitals / italic) measured on the built part. When every
  clause is already true, the note's status line says "already one line, nothing to change", and Run with only
  such notes (nothing drawn) ends at once with "nothing to change — ..." (no reading, no tokens). Any clause it
  doesn't understand, or one that isn't true yet, runs the fix as before.
- **A place-only fix note typed in the gap between parts finds its part**: "one line, below heading" typed in
  the empty space between the heading and the subtitle (round 32 c2) used to land "placed here" and go to the
  whole page; now the nearest heading within reach is the named part and the note binds to the part below it.
  Seen live: "on this element · p (the part below the heading)".
- The hand session's Run returns `nothing: true` when the tool says there is nothing to change.
- Unit tests: 5 new cases for `alreadySo` (round 32 c2 subtitle one line; two lines still fixed; any other ask runs).
