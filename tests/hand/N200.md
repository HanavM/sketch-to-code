# n200: a delete fix removes only what its note names, never the card around it

Found in n198 (round 45 e1 car rental): the first build painted a huge "500" over the Fiat card. The fix note
"delete the huge grey 500" was read as a delete of the card's div and the whole first card went; a second fix
brought it back with invented words.

## What was built
- **Delete narrows to the named thing** (`pipeline/src/narrowdelete.ts`, called in grounding): when a delete
  note names text ("500", or quoted words) and a smaller element on the target reads exactly that, the delete is
  that element. Verbs, look words (huge, grey, faded, watermark) and colours are not counted as names. An element
  that only *contains* the words ("Fiat 500") never matches, so the card title is safe; "delete this card" keeps
  the card. "huge" picks the biggest match, otherwise the one under the note, else the smallest.
- **The plan names what goes before Go**: the narrowed target is the one the held plan shows ("DELETE · <span> "500"")
  and the grounded reading lists it under `narrowedDeletes`.
- Tests: `pipeline/tests/n200-narrow-delete.test.ts` (6).

## Did it help
- Yes on this page: one fix instead of two, 11 fewer words, 5 fewer minutes, 78.7 → 85.3.
- Honest limit: this time the fix note landed on the "500" span itself (the bench said "on this element · span"),
  so the model may have picked the span without the new rule. The rule is proven by the unit test of the n198
  case (card picked, note on the 500 → the 500 only), not yet by a live run where the card was picked.
- Not touched: the build still paints a giant word from "Fiat 500" (the decoration gap). Next lead.
